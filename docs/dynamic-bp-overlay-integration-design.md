# 动态 BP 动画页接入设计稿

> 状态：已接入，并于 v1.6.0 完成业务顺序与动画修订  
> 日期：2026-08-01  
> 目标版本：建议作为 v1.6.0 的主体功能

## 1. 结论

项目中的动态 BP 动画页已经具备完整的 1920×1080 视觉结构和入场动画，可以接入现有 BP 系统，但不能直接把当前页面 URL 填入 OBS 后就投入使用。

当前页面仍是演示稿：队伍、比分、Ban/Pick、赛区、轮次和 30 秒倒计时全部写死，并且页面只会自行重播。现有 `/api/bp/events` 虽然能实时发送 BP 会话变化，但没有“当前正在播出的唯一会话”概念，直接订阅会产生 A/B 房、不同场次和重赛记录串台的风险。

推荐方案是：保留现有演示页作为视觉基准，新增一个正式动态 BP Overlay，由后端提供唯一的展示快照和实时事件。OBS 中已有的“BP动态底板”作为覆盖层放在旧 BP 视觉之上，但旧 BP 图层和旧同步逻辑始终保留并继续运行。

BP 控制页增加“启用动态 BP”开关。关闭时只执行旧 OBS 同步，动态网页保持全透明；开启时旧 OBS 与 Overlay 双轨更新。Overlay 关闭、断线、失效、素材不完整或未收到有效播放指令时，也必须全透明，让下方已经同步好的旧 BP 画面立即成为兜底。

## 2. 已读取的现状

### 2.1 动画页

现有文件：

- `public/bp-animation-design.html`
- `public/assets/css/bp-animation-design.css`
- `public/assets/js/bp-animation-design.js`

现有能力：

- 1920×1080、16:9 固定构图。
- 视频动态背景 `zhuifeng-base.mp4`。
- 逃生方 8 个 Pick 位、追捕方 2 个 Pick 位、3 个 Ban 位。
- 队徽、队名、比分、赛区、轮次、MATCH 局数。
- 两位数图片倒计时和连续收缩时间条。
- 面板、队伍、比分、角色槽位和 Ban 位分层入场动画。
- 已有 Playwright 视觉坐标、素材尺寸、动画曲线和非空画布验证。

当前限制：

- 所有展示数据写死在 HTML 中。
- 倒计时固定 30 秒，不读取七阶段独立时长。
- 角色更新不会单独触发动画。
- 页面刷新后不知道应恢复哪一场、哪一局、哪个房间。
- 页面会在加载时自动播放，尚未与 OBS 场景切换时机绑定。

### 2.2 后端 BP 状态

现有 `BpService` 已经提供接入所需的原始数据：

- 唯一会话 ID：比赛、BO3 局数、房间、正赛/重赛。
- 当前阶段、阶段完成状态和 600ms 的归零脉冲。
- 每阶段独立倒计时时长、deadline 和剩余秒数。
- 3 个 Ban 槽位、10 个 Pick 槽位。
- 队伍角色映射、比分、输出模式、赛果和历史版本。
- `session`、`timer`、`push-slot`、`clear-slot` 等实时事件。

不足之处是：当前 SSE 会广播所有会话的事件，并且连接时只发送 OBS 状态，不发送当前 BP 展示快照。因此正式 Overlay 需要独立的展示状态层。

## 3. 目标与边界

### 3.1 本次接入目标

1. OBS 使用固定 URL：`http://127.0.0.1:3788/bp-overlay.html`。
2. 保留当前坐标、尺寸、字体和素材结构，动画节奏可在不改变业务映射的前提下独立迭代。
3. BP 控制页的选择、清空、重置、回溯和重赛能实时反映到 Overlay。
4. 七阶段倒计时使用各自配置，并严格保留“先显示 0，再进入下一阶段”的行为。
5. 页面或后端重连后恢复当前正确快照，不串场、不重复计分、不重新推进流程。
6. BP 控制页提供持久化的“启用动态 BP”开关，默认关闭以保证安全。
7. 动态开启时，旧 OBS 与 Overlay 同时同步；动态关闭时只执行旧 OBS 同步。
8. 点击“切换场景至 BP”且动态开启时，在 OBS 确认完成切场后等待 2 秒，再显示并启动动态入场。
9. 动态网页在关闭或任何失效状态下必须整页全透明，不能保留最后一帧或错误底色。
10. 旧 OBS BP 图层与旧推送逻辑完整保留，随时可作为即时兜底。

### 3.2 不在本次范围内

- 不修改本场赛果、晋级图、今日赛程和控制台场景逻辑。
- 不删除、不停用旧 BP 图片源、文字源或分组。
- 不把 OBS WebSocket 密码暴露给浏览器页。
- 不让 Overlay 直接连接 OBS；所有 OBS 操作仍由后端串行执行。

## 4. 推荐架构

```text
BP 控制页
   |
   | HTTP 操作
   v
BpService（现有业务状态）
   |                         |
   | 旧 OBS 同步（始终执行） | 动态展示快照（开关开启时）
   v                         v
旧 BP 图片/文字源        BpPresentationService（新增）
                             |             |
                             | GET 快照    | SSE 实时事件
                             v             v
                       bp-overlay.html / bp-overlay.js
                             |
                             v
                       OBS 浏览器源“BP动态底板”
```

OBS WebSocket 只负责：

- 校验“BP动态底板”是否存在。
- 将其 URL 固定为正式 Overlay 地址。
- 保证动态源位于旧 BP 视觉之上，但不修改旧视觉分组的启用状态。
- 保存并应用“启用动态 BP”开关；关闭或失效时向 Overlay 下发透明状态。
- 按现有 BP 转场流程切换场景。

浏览器 Overlay 通过本地 HTTP + SSE 接收数据。这里不需要再增加第二套 WebSocket：Overlay 是单向接收状态，SSE 自带断线重连，且与项目现有 BP 实时通道一致。

## 6. 唯一展示会话

这是整个接入中最重要的约束。

不能让 Overlay 根据“最近更新时间”自行猜测当前比赛。系统必须保存一个明确的 `activeSessionId`。只有该会话的变化允许进入动态覆盖层，其他房间、其他比赛和历史记录的事件全部忽略。旧 OBS 同步不受这个展示状态影响，继续按现有控制页会话执行。

建议规则：

- 单独点击“载入”：只更新控制页，不改变正在播出的 Overlay。
- 点击“同步 OBS”：旧 OBS 始终完整同步；动态开关开启时额外将当前会话设为展示会话并预载 Overlay 快照，但不显示、不重播整套入场。
- 点击“切换场景至 BP”：旧 OBS 始终完整同步；动态开启时先让 Overlay 保持透明并预载，再切场，切场确认后 2 秒才显示并触发完整入场。
- 动态开关关闭：立刻广播 `disabled`，Overlay 全透明；之后所有 BP 操作只走旧 OBS 流程。
- Overlay 不在线或预载失败：不阻止旧 OBS 切场，只记录动态层告警并保持透明。
- 点击“载入并切换”：沿用其现有本场对决流程，不触发 BP Overlay 入场。
- 创建重赛并载入：只有再次执行“同步 OBS”或“切换场景至 BP”后，重赛记录才成为动态层的展示快照。

展示状态示例：

```json
{
  "schemaVersion": 1,
  "dynamicEnabled": true,
  "activeSessionId": "mobile-2026-07-25-qf-1:g1:rA:a1",
  "sequence": 142,
  "introEpoch": 8,
  "visibility": "armed",
  "playAt": 1785547200000,
  "commandExpiresAt": 1785547201500,
  "reason": "slot-updated",
  "snapshot": {}
}
```

- `sequence` 单调递增，Overlay 忽略旧事件。
- `introEpoch` 只在需要完整入场时递增，防止 SSE 重连导致重复播放。
- `visibility` 只有在有效播放窗口内才会从 `hidden/armed` 进入 `live`。
- `playAt` 是 OBS 确认切到 BP 后 2 秒的绝对时间。
- `commandExpiresAt` 防止离线 Overlay 恢复后迟到播放，错过窗口就继续透明并等待下次切场。
- `snapshot` 始终是完整状态，不依赖浏览器自行拼接多条历史事件。

## 7. 展示快照

后端应直接返回可渲染数据，浏览器不负责读取赛事 JSON、查找昵称或解析磁盘路径。

快照至少包含：

- 会话：ID、状态、阶段、局数、房间、正赛/重赛。
- 队伍：逃生方和追捕方的展示名、Web 队徽 URL。
- 比分：逃生方、追捕方。
- 元数据：赛区、轮次、`MATCH n`、比赛阶段图片 URL。
- 计时：阶段总时长、deadline、剩余秒数、是否运行、是否处于归零脉冲。
- 槽位：角色 ID、角色图片 URL、显示文本、是否完成。
- 输出模式：选手昵称或角色称号。

所有图片 URL 必须是项目内的白名单 Web 路径，不能把 `E:\...` 绝对路径发送给浏览器。

## 9. 动画状态机

Overlay 分为六种状态：

1. `transparent`：默认状态，整页 alpha 为 0，不绘制底色。
2. `booting`：仍保持透明，在后台加载背景视频、布局图、数字图、队徽和当前角色图片。
3. `armed`：快照和素材已就绪，但继续透明，等待有效 `playAt`。
4. `intro`：到达 `playAt` 后整页显示并执行一次完整 BP 面板入场。
5. `live`：动态层有效，只响应单槽位、比分和倒计时变化。
6. `invalid`：开关关闭、心跳超时、SSE 断线、素材失败、会话无效或播放指令过期；立即回到全透明。

HTML、`body` 和根容器的默认背景都必须为 `transparent`。不能像现有设计稿一样保留 `#070a18` 或 `#080b1d` 作为失效底色；背景视频和整个舞台必须统一包在受有效状态控制的根节点内。

增加独立心跳，每秒更新一次动态页有效期。根节点使用 3 秒失效看门狗：如果 JavaScript、SSE 或后端停止刷新有效期，CSS/WAAPI 自动将整页 alpha 归零。这样后端关闭、页面卡住或事件通道失效时，不依赖用户额外操作也会露出下方旧 BP 画面。

### 9.1 完整入场

切场前，后端先下发 `armed`，让 Overlay 清空可见状态并保持透明。OBS 确认当前节目场景已经变为 BP 后，后端计算 `playAt = 确认时间 + 2000ms` 并递增 `introEpoch`。Overlay 到达该时间点后才变为可见，并从第 0 帧播放面板亮度展开、队伍信息入场和已完成槽位顺序呈现。

倒计时页提供持久化的展开模式选择：`classic` 使用上一版自下而上的经典展开，`luminance` 使用当前中心亮度擦开。模式变更不打断当前画面，从下一次动态 BP 入场开始生效。

2 秒延迟从 OBS 确认切场成功开始计算，不从用户点击按钮或发出请求时计算。切场失败、动态开关在等待期间关闭、会话改变或新切场指令覆盖旧指令时，旧的延迟任务立即取消，Overlay 保持透明。

入场前已经锁定的角色按原槽位延迟出现；空槽位保持隐藏。这样载入历史 BP 或重赛快照时，仍能以完整动画展示原 BP。

### 9.2 单槽位更新

BP 场景已经显示时：

- 选择完成一个 Pick：只播放该卡片的亮度擦入与昵称入场。
- 选择完成一个 Ban：只播放该 Ban 位的高亮擦入和灰度收束动画。
- 清空槽位：淡出并恢复空状态，不重播整个面板。
- 恢复历史版本或重置：先预加载新快照所需图片，再原子替换，避免逐格闪烁。

### 9.3 倒计时

数字显示和时间条必须共用后端 deadline：

- 数字仍固定两位。
- 时间条按 `剩余毫秒 / 当前阶段总毫秒` 连续收缩，不按每秒跳变。
- SSE 每秒事件只用于校正，浏览器本地依据 deadline 平滑运行。
- 阶段完成后显示 0，并保持配置中的 600ms 归零脉冲。
- 下一阶段从该阶段配置值开始，不再硬编码 30 秒。
- 页面重连时从 deadline 计算当前位置，不从完整长度重新开始；但如果动态播放指令已经过期，则即使快照有效也保持透明，不能迟到覆盖旧 BP 画面。

## 10. BP 按钮流程调整

“切换场景至 BP”的最终顺序建议为：

1. 载入当前会话。
2. 无论动态开关状态如何，都执行现有旧 OBS 完整同步。
3. 如果动态开关关闭：广播 `disabled` 让网页全透明，然后直接按旧流程切到 BP，流程结束。
4. 如果动态开关开启：将当前会话设为唯一展示会话，广播完整快照和 `armed`，Overlay 继续透明并后台预载。
5. 校验“BP动态底板”URL 和图层顺序。Overlay 在线则记录已就绪；离线或素材失败只记录警告，不阻止旧 OBS 流程。
6. 使用现有“2026追风杯”转场切换到 BP。
7. 等待 OBS 的当前节目场景确认变为 BP。
8. 从确认时刻开始等待 2000ms。
9. 等待期间若开关关闭、会话变化、切离 BP 或出现更新的切场指令，则取消本次动态播放。
10. 延迟完成后广播新的 `introEpoch` 和短时有效播放指令，Overlay 显示并从第 0 帧开始完整入场。

旧 OBS 同步或场景切换失败时仍按现有规则阻止切场并显示错误；动态 Overlay 自身失败时不阻止切场，网页保持透明并显示动态层警告，因为旧 BP 画面已经同步完成。

BP 页增加一个持久化开关和一条状态：

- 开关：`启用动态 BP`，默认关闭。
- 开启：旧 OBS 与 Overlay 同时接收后续 BP 更新。
- 关闭：立即让 Overlay 全透明，后续只执行旧 OBS 同步。
- 位置：放在 BP 顶部条件卡的常驻操作区，不能收进菜单或随页面滚动消失。
- 关闭动作不弹二次确认，保证突发情况下可以一键立即降级；开启后只预热，不会突然覆盖当前画面。

- 状态：`动态 BP：已关闭 / 预载中 / 待播放 / 2 秒延迟 / 动画运行中 / 已降级到旧 BP`。

不增加额外的“播放动画”日常按钮，避免导播需要多一步操作。重播功能只放在诊断入口中。

## 11. OBS 接入与迁移

### 11.1 浏览器源设置

复用现有输入源 `BP动态底板`：

- URL：`http://127.0.0.1:3788/bp-overlay.html`
- 宽度：1920
- 高度：1080
- FPS：与 OBS 当前输出一致。
- 不在场景隐藏时关闭源，使 SSE 和素材预加载保持在线。
- 不通过浏览器源输出音频，原 BP 音频采集保持不变。

连接 OBS 时校验该源；URL 不正确时由后端修正，不要求用户手动修改。

### 11.2 双轨图层关系

- `BP动态底板` 位于所有旧 BP 视觉之上。
- 旧视觉项目 `BP底图`、`BP底板`、`BP数据`、`Pick立绘`、`Pick昵称`、`Ban位`、`对局基础信息`、`比赛阶段` 始终保持启用。
- 旧 `pushSlot`、`clearSlot`、倒计时、比分和完整同步逻辑全部保留，继续通过串行队列使用“暗”和“暗T”。
- 动态层有效且运行时使用自身不透明的背景视频覆盖旧视觉，因此画面中只看到动态版。
- 动态层透明、被禁用或失效时，下方旧 BP 画面立即显现，无需重新同步和切场。
- Overlay 不写入 OBS 图片或文字源，因此不会额外争用“暗”和“暗T”。

### 11.3 动态开关

`dynamicEnabled` 是全局持久化设置，默认值为 `false`。

开启时：

1. 修正并加载浏览器源 URL。
2. 启用 `BP动态底板` 场景项目，但网页仍保持透明。
3. 开始接收会话快照、心跳和素材预载。
4. 所有后续 BP 操作同时更新旧 OBS 和 Overlay 状态。
5. 只有“切换场景至 BP”的 2 秒延迟播放指令能让网页显示。

关闭时：

1. 先向 Overlay 广播 `disabled`，要求 DOM 立即全透明。
2. 再通过 OBS WebSocket 停用 `BP动态底板` 场景项目，作为第二重保险。
3. 取消尚未执行的 2 秒播放任务和当前 `introEpoch`。
4. 后续 BP 操作只执行旧 OBS 同步。
5. 不清除展示快照，重新开启时可以后台预载，但不会自动显示。

## 12. 即时降级与配置恢复

本方案不再需要停用旧图层，也不需要恢复旧推送逻辑，因为旧逻辑从未停止。

日常即时降级就是关闭“启用动态 BP”开关：网页先透明、浏览器场景项再停用，当前 BP 场景不切换，旧画面立即接管。

首次配置浏览器源前仍保存：

- `BP动态底板` 原 URL、宽高和输入设置。
- `BP动态底板` 原场景项目启用状态和层级。

如果需要完全撤销动态功能，只恢复该浏览器源配置；旧 BP 图层不需要做任何恢复操作。

## 13. 容错与安全

- SSE 断线后自动重连并重新获取完整快照，但断线发生时先让整页全透明。
- 心跳超过 3 秒未刷新、后端关闭、页面失效或 JavaScript 卡住时，看门狗自动归零整页 alpha。
- 任意必要图片或视频加载失败时不展示残缺动态页，整页透明并报告具体素材。
- 动态开关关闭时同时执行网页透明和 OBS 场景项停用，避免单点失效。
- 浏览器只接收白名单资源 URL，不接收或访问任意绝对路径。
- Overlay 接口不返回 OBS 密码和本机敏感配置。
- 所有旧 BP OBS 同步和浏览器源开关操作继续通过 `ObsController.runOperation()` 串行执行。
- 不允许根据最近事件自动切换展示会话，必须显式激活。

## 14. 测试与验收

### 14.1 自动测试

- 展示会话在 A/B 房和不同比赛之间严格隔离。
- 重赛、回溯、重置和手动结束能生成正确快照。
- 七阶段时长、0 脉冲和 deadline 重连恢复正确。
- Pick 每个槽位独立更新，Ban/Pick 不串位。
- 昵称与角色称号输出模式正确。
- 1920×1080 截图中所有素材加载成功、画布非空、坐标不变。
- 入场动画、单槽动画和时间条曲线通过 Playwright 定点截图。
- 动态开关关闭时只调用旧 OBS 流程，Overlay 保持透明。
- 动态开关开启时，旧 OBS 推送与 Overlay 快照均能收到同一次 BP 更新。
- OBS 确认切到 BP 后未满 2000ms 时 Overlay 必须透明；到达 2000ms 后才开始第 0 帧入场。
- 开关关闭、会话变化、切离 BP 和重复切场能取消尚未执行的播放任务。
- SSE 断线、心跳超时、必要素材失败和过期播放指令都会触发整页透明。
- 旧 BP 的“暗 / 暗T”中转流程在动态开启时仍然执行，并保持原有串行约束。
- OBS 源 URL、场景项双保险开关和浏览器源配置恢复使用 mock WebSocket 验证。

### 14.2 实机验收

1. 保持动态开关关闭，完成一场旧 BP，确认行为与接入前完全一致。
2. 开启动态 BP，在 OBS 未处于 BP 场景时载入并预热一场 BP。
3. 点击“切换场景至 BP”，切场后的前 2 秒只显示旧 BP；满 2 秒后动态页从第 0 帧开始入场。
4. 逐步执行七个阶段，确认旧 OBS 源与 Overlay 同时更新，最终画面只看到上层动态版。
5. 动态运行中关闭开关，确认不切场、不重新同步，动态层立即消失并露出状态一致的旧 BP。
6. 分别关闭后端、断开 SSE、制造必要素材失败，确认动态网页在 3 秒内全透明。
7. 检查每次阶段切换均先显示 0，再从配置时长开始。
8. 切换 A/B 房、BO3 局数和重赛记录，确认不会串台。
9. 恢复浏览器源原配置，确认不会影响旧 BP 输出。

## 16. 建议确认项

本版已按确认要求改为“旧 BP 始终运行，动态 BP 作为可开关覆盖层”的双轨方案。动态层只有在开关开启、状态有效且收到切场后 2 秒播放指令时可见，其余状态一律全透明。

需要确认的核心表现只有一项：Pick 卡片顶部文字继续遵循当前控制页的“选手昵称 / 角色称号”开关。默认建议保持现有语义，不额外同时显示两行文字，以免改变已经定稿的动画版式。
